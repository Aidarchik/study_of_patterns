# Порождающие паттерны проектирования

- Фабричный метод
- Абстрактная фабрика
- Строитель
- Прототип
- Одиночка


> >### Фабричный метод — это порождающий паттерн проектирования, который определяет общий интерфейс для создания объектов в суперклассе, позволяя подклассам изменять тип создаваемых объектов.

| Плюсы                                                                              | Минусы                                                                                                                                              |
|------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------|
| &#10004; Избавляет класс от привязки к конкретным классам продуктов.               | &#10006; Может привести к созданию больших параллельных иерархий классов, так как для каждого класса продукта надо создать свой подкласс создателя. |
| &#10004; Выделяет код производства продуктов в одно место, упрощая поддержку кода. |                                                                                                                                                     |
| &#10004; Упрощает добавление новых продуктов в программу.                          |                                                                                                                                                     |
| &#10004; Реализует принцип открытости/закрытости.                                  |                                                                                                                                                     |

>###  Абстрактная фабрика — это порождающий паттерн проектирования, который позволяет создавать семейства связанных объектов, не привязываясь к конкретным классам создаваемых объектов.

| Плюсы                                                                              | Минусы                                                                            |
|------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| &#10004; Гарантирует сочетаемость создаваемых продуктов.                           | &#10006; Усложняет код программы из-за введения множества дополнительных классов. |
| &#10004; Избавляет клиентский код от привязки к конкретным классам продуктов.      | &#10006; Требует наличия всех типов продуктов в каждой вариации.                  |
| &#10004; Выделяет код производства продуктов в одно место, упрощая поддержку кода. |                                                                                   |
| &#10004; Упрощает добавление новых продуктов в программу.                          |                                                                                   |
| &#10004; Реализует принцип открытости/закрытости.                                  |                                                                                   |

>### Строитель — это порождающий паттерн проектирования, который позволяет создавать сложные объекты пошагово. Строитель даёт возможность использовать один и тот же код строительства для получения разных представлений объектов.

| Плюсы                                                                               | Минусы                                                                                                                                    |
|-------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------|
| &#10004; Позволяет создавать продукты пошагово.                                     | &#10006; Усложняет код программы из-за введения дополнительных классов.                                                                   |
| &#10004; Позволяет использовать один и тот же код для создания различных продуктов. | &#10006; Клиент будет привязан к конкретным классам строителей, так как в интерфейсе директора может не быть метода получения результата. |
| &#10004; Изолирует сложный код сборки продукта от его основной бизнес-логики.       |

>### Прототип — это порождающий паттерн проектирования, который позволяет копировать объекты, не вдаваясь в подробности их реализации.

| Плюсы                                                                            | Минусы                                         |
|----------------------------------------------------------------------------------|------------------------------------------------|
| &#10004; Позволяет клонировать объекты, не привязываясь к их конкретным классам. | &#10006; Сложно клонировать составные объекты, |
| &#10004; Меньше повторяющегося кода инициализации объектов.                      |                                                |
| &#10004; Ускоряет создание объектов.                                             |                                                |
| &#10004; Альтернатива созданию подклассов для конструирования сложных объектов.  |                                                |


>### Одиночка — это порождающий паттерн проектирования, который гарантирует, что у класса есть только один экземпляр, и предоставляет к нему глобальную точку доступа.

| Плюсы                                                         | Минусы                                                                     |
|---------------------------------------------------------------|----------------------------------------------------------------------------|
| &#10004; Гарантирует наличие единственного экземпляра класса. | &#10006; Нарушает принцип единственной ответственности класса.             |
| &#10004; Предоставляет к нему глобальную точку доступа.       | &#10006; Маскирует плохой дизайн.                                          |
| &#10004; Реализует отложенную инициализацию объекта-одиночки. | &#10006; Проблемы мультипоточности.                                        |
|                                                               | &#10006; Требует постоянного создания Mock-объектов при юнит-тестировании. |


# Структурные паттерны проектирования

- Адаптер
- Мост
- Компоновщик
- Декоратор
- Фасад
- Легковес
- Заместитель

>### Адаптер — это структурный паттерн проектирования, который позволяет объектам с несовместимыми интерфейсами работать вместе.

| Плюсы    | Минусы   |
|----------|----------|
| &#10004; Отделяет и скрывает от клиента подробности преобразования различных интерфейсов.| &#10006; Усложняет код программы из-за введения дополнительных классов.|

>### Мост — это структурный паттерн проектирования, который разделяет один или несколько классов на две отдельные иерархии — абстракцию и реализацию, позволяя изменять их независимо друг от друга.

| Плюсы                                                                       | Минусы                                                                  |
|-----------------------------------------------------------------------------|-------------------------------------------------------------------------|
| &#10004; Позволяет строить платформо-независимые программы.                 | &#10006; Усложняет код программы из-за введения дополнительных классов. |
| &#10004; Скрывает лишние или опасные детали реализации от клиентского кода. |                                                                         |
| &#10004; Реализует принцип открытости/закрытости.                           |                                                                         |

>### Компоновщик — это структурный паттерн проектирования, который позволяет сгруппировать множество объектов в древовидную структуру, а затем работать с ней так, как будто это единичный объект.

| Плюсы                                                                            | Минусы                                         |
|----------------------------------------------------------------------------------|------------------------------------------------|
| &#10004; Упрощает архитектуру клиента при работе со сложным деревом компонентов. | &#10006; Создаёт слишком общий дизайн классов. |
| &#10004; Облегчает добавление новых видов компонентов.                           |                                                |

>### Декоратор — это структурный паттерн проектирования, который позволяет динамически добавлять объектам новую функциональность, оборачивая их в полезные «обёртки».

| Плюсы                                                                                         | Минусы                                                         |
|-----------------------------------------------------------------------------------------------|----------------------------------------------------------------|
| &#10004; Большая гибкость, чем у наследования.                                                | &#10006; Трудно конфигурировать многократно обёрнутые объекты. |
| &#10004; Позволяет добавлять обязанности на лету.                                             | &#10006; Обилие крошечных классов.                             |
| &#10004; Можно добавлять несколько новых обязанностей сразу.                                  |                                                                |
| &#10004; Позволяет иметь несколько мелких объектов вместо одного объекта на все случаи жизни. |                                                                |

>### Фасад — это структурный паттерн проектирования, который предоставляет простой интерфейс к сложной системе классов, библиотеке или фреймворку.

| Плюсы    | Минусы   |
|----------|----------|
| &#10004; Изолирует клиентов от компонентов сложной подсистемы.| &#10006; Фасад рискует стать божественным объектом, привязанным ко всем классам программы.|

>### Легковес — это структурный паттерн проектирования, который позволяет вместить бóльшее количество объектов в отведённую оперативную память. Легковес экономит память, разделяя общее состояние объектов между собой, вместо хранения одинаковых данных в каждом объекте.

| Плюсы                                 | Минусы                                                                            |
|---------------------------------------|-----------------------------------------------------------------------------------|
| &#10004; Экономит оперативную память. | &#10006; Расходует процессорное время на поиск/вычисление контекста.              |
|                                       | &#10006; Усложняет код программы из-за введения множества дополнительных классов. |

>### Заместитель — это структурный паттерн проектирования, который позволяет подставлять вместо реальных объектов специальные объекты-заменители. Эти объекты перехватывают вызовы к оригинальному объекту, позволяя сделать что-то до или после передачи вызова оригиналу.

| Плюсы                                                                     | Минусы                                                                  |
|---------------------------------------------------------------------------|-------------------------------------------------------------------------|
| &#10004; Позволяет контролировать сервисный объект незаметно для клиента. | &#10006; Усложняет код программы из-за введения дополнительных классов. |
| &#10004; Может работать, даже если сервисный объект ещё не создан.        | &#10006; Увеличивает время отклика от сервиса.                          |
| &#10004; Может контролировать жизненный цикл служебного объекта.          |                                                                         |

# Поведенческие паттерны проектирования

- Цепочка обязанностей
- Команда
- Итератор
- Посредник
- Снимок
- Наблюдатель
- Состояние
- Стратегия
- Шаблонный метод
- Посетитель

>### Цепочка обязанностей — это поведенческий паттерн проектирования, который позволяет передавать запросы последовательно по цепочке обработчиков. Каждый последующий обработчик решает, может ли он обработать запрос сам и стоит ли передавать запрос дальше по цепи.

| Плюсы                                                          | Минусы                                                |
|----------------------------------------------------------------|-------------------------------------------------------|
| &#10004; Уменьшает зависимость между клиентом и обработчиками. | &#10006; Запрос может остаться никем не обработанным. |
| &#10004;  Реализует принцип единственной обязанности.          |                                                       |
| &#10004; Реализует принцип открытости/закрытости.              |                                                       |


>### Команда — это поведенческий паттерн проектирования, который превращает запросы в объекты, позволяя передавать их как аргументы при вызове методов, ставить запросы в очередь, логировать их, а также поддерживать отмену операций.

| Плюсы                                                                                                                         | Минусы                                                                            |
|-------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| &#10004; Убирает прямую зависимость между объектами, вызывающими операции, и объектами, которые их непосредственно выполняют. | &#10006; Усложняет код программы из-за введения множества дополнительных классов. |
| &#10004; Позволяет реализовать простую отмену и повтор операций.                                                              |                                                                                   |
| &#10004; Позволяет реализовать отложенный запуск операций.                                                                    |                                                                                   |
| &#10004; Позволяет собирать сложные команды из простых.                                                                       |                                                                                   |
| &#10004; Реализует принцип открытости/закрытости.                                                                             |                                                                                   |

>### Итератор — это поведенческий паттерн проектирования, который даёт возможность последовательно обходить элементы составных объектов, не раскрывая их внутреннего представления.

| Плюсы                                                                              | Минусы                                                    |
|------------------------------------------------------------------------------------|-----------------------------------------------------------|
| &#10004; Упрощает классы хранения данных.                                          | &#10006; Не оправдан, если можно обойтись простым циклом. |
| &#10004; Позволяет реализовать различные способы обхода структуры данных.          |                                                           |
| &#10004; Позволяет одновременно перемещаться по структуре данных в разные стороны. |                                                           |

>### Посредник — это поведенческий паттерн проектирования, который позволяет уменьшить связанность множества классов между собой, благодаря перемещению этих связей в один класс-посредник.

| Плюсы                                                                                 | Минусы                                     |
|---------------------------------------------------------------------------------------|--------------------------------------------|
| &#10004; Устраняет зависимости между компонентами, позволяя повторно их использовать. | &#10006; Посредник может сильно раздуться. |
| &#10004; Упрощает взаимодействие между компонентами.                                  |                                            |
| &#10004; Централизует управление в одном месте.                                       |                                            |

>### Снимок — это поведенческий паттерн проектирования, который позволяет сохранять и восстанавливать прошлые состояния объектов, не раскрывая подробностей их реализации.

| Плюсы                                                                                                | Минусы                                                                                                                                             |
|------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| &#10004; Не нарушает инкапсуляции исходного объекта.                                                 | &#10006; Требует много памяти, если клиенты слишком часто создают снимки.                                                                          |
| &#10004; Упрощает структуру исходного объекта. Ему не нужно хранить историю версий своего состояния. | &#10006; Может повлечь дополнительные издержки памяти, если объекты, хранящие историю, не освобождают ресурсы, занятые устаревшими снимками.       |
|                                                                                                      | &#10006; В некоторых языках (например, PHP, Python, JavaScript) сложно гарантировать, чтобы только исходный объект имел доступ к состоянию снимка. |

>### Наблюдатель — это поведенческий паттерн проектирования, который создаёт механизм подписки, позволяющий одним объектам следить и реагировать на события, происходящие в других объектах.

| Плюсы                                                                      | Минусы                                               |
|----------------------------------------------------------------------------|------------------------------------------------------|
| &#10004; Издатели не зависят от конкретных классов подписчиков и наоборот. | &#10006; Подписчики оповещаются в случайном порядке. |
| &#10004; Вы можете подписывать и отписывать получателей на лету.           |                                                      |
| &#10004; Реализует принцип открытости/закрытости.                          |                                                      |

>### Состояние — это поведенческий паттерн проектирования, который позволяет объектам менять поведение в зависимости от своего состояния. Извне создаётся впечатление, что изменился класс объекта.
| Плюсы                                                                          | Минусы                                                                               |
|--------------------------------------------------------------------------------|--------------------------------------------------------------------------------------|
| &#10004; Избавляет от множества больших условных операторов машины состояний.  | &#10006; Может неоправданно усложнить код, если состояний мало и они редко меняются. |
| &#10004; Концентрирует в одном месте код, связанный с определённым состоянием. |                                                                                      |
| &#10004; Упрощает код контекста.                                               |                                                                                      |

>### Стратегия — это поведенческий паттерн проектирования, который определяет семейство схожих алгоритмов и помещает каждый из них в собственный класс, после чего алгоритмы можно взаимозаменять прямо во время исполнения программы.

| Плюсы                                                            | Минусы                                                                                           |
|------------------------------------------------------------------|--------------------------------------------------------------------------------------------------|
| &#10004; Горячая замена алгоритмов на лету.                      | &#10006; Усложняет программу за счёт дополнительных классов.                                     |
| &#10004; Изолирует код и данные алгоритмов от остальных классов. | &#10006; Клиент должен знать, в чём состоит разница между стратегиями, чтобы выбрать подходящую. |
| &#10004; Уход от наследования к делегированию.                   |                                                                                                  |
| &#10004; Реализует принцип открытости/закрытости.                |                                                                                                  |

>### Шаблонный метод — это поведенческий паттерн проектирования, который определяет скелет алгоритма, перекладывая ответственность за некоторые его шаги на подклассы. Паттерн позволяет подклассам переопределять шаги алгоритма, не меняя его общей структуры.

| Плюсы                                            | Минусы                                                                                                                              |
|--------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| &#10004; Облегчает повторное использование кода. | &#10006; Вы жёстко ограничены скелетом существующего алгоритма.                                                                     |
|                                                  | &#10006; Вы можете нарушить принцип подстановки Барбары Лисков, изменяя базовое поведение одного из шагов алгоритма через подкласс. |
|                                                  | &#10006; С ростом количества шагов шаблонный метод становится слишком сложно поддерживать.                                          |

>### Посетитель — это поведенческий паттерн проектирования, который позволяет добавлять в программу новые операции, не изменяя классы объектов, над которыми эти операции могут выполняться.
| Плюсы                                                                               | Минусы                                                                |
|-------------------------------------------------------------------------------------|-----------------------------------------------------------------------|
| &#10004; Упрощает добавление операций, работающих со сложными структурами объектов. | &#10006; Паттерн не оправдан, если иерархия элементов часто меняется. |
| &#10004; Объединяет родственные операции в одном классе.                            | &#10006; Может привести к нарушению инкапсуляции элементов.           |
| &#10004; Посетитель может накапливать состояние при обходе структуры элементов.     |                                                                       |
