# Паттерны проектирования

## Порождающие паттерны

### 1. Factory Method — Фабричный метод

**Тип:** порождающий паттерн проектирования.

**Определение:**  
Определяет общий интерфейс для создания объектов, позволяя подклассам решать, какой конкретный объект создавать.

**Ключевая мысль:**  
Создание объекта выносится в отдельный метод.

**Пример:**  
`NotificationFactory` создаёт разные типы уведомлений: `EmailNotification`, `SmsNotification`, `PushNotification`.

---

### 2. Abstract Factory — Абстрактная фабрика

**Тип:** порождающий паттерн проектирования.

**Определение:**  
Предоставляет интерфейс для создания семейств связанных объектов, не привязывая код к конкретным классам.

**Ключевая мысль:**  
Одна фабрика создаёт несколько связанных между собой объектов.

**Пример:**  
`WindowsFactory` создаёт `WindowsButton` и `WindowsCheckbox`, а `MacFactory` — `MacButton` и `MacCheckbox`.

---

### 3. Builder — Строитель

**Тип:** порождающий паттерн проектирования.

**Определение:**  
Позволяет пошагово создавать сложный объект, отделяя процесс его создания от самого объекта.

**Ключевая мысль:**  
Сложный объект собирается по шагам.

**Пример:**
```java
User user = User.builder()
        .name("Ivan")
        .age(25)
        .email("ivan@example.com")
        .build();
```

---

### 4. Prototype — Прототип

**Тип:** порождающий паттерн проектирования.

**Определение:**  
Позволяет создавать новые объекты путём копирования уже существующего объекта-прототипа.

**Ключевая мысль:**  
Не создаём объект с нуля — копируем готовый.

**Пример:**  
Есть настроенный объект документа. Вместо повторной настройки создаём его копию и изменяем необходимые поля.

---

### 5. Singleton — Одиночка

**Тип:** порождающий паттерн проектирования.

**Определение:**  
Гарантирует, что у класса существует только один экземпляр, и предоставляет к нему глобальную точку доступа.

**Ключевая мысль:**  
Один класс — один экземпляр.

**Пример:**  
Единый объект конфигурации приложения.

---

# Структурные паттерны

### 6. Adapter — Адаптер

**Тип:** структурный паттерн проектирования.

**Определение:**  
Позволяет объектам с несовместимыми интерфейсами работать вместе, преобразуя интерфейс одного объекта в интерфейс, ожидаемый клиентом.

**Ключевая мысль:**  
Адаптер переводит один интерфейс в другой.

**Пример:**  
Старый сервис имеет метод `pay()`, а новый код ожидает `makePayment()`. Адаптер связывает эти два интерфейса.

---

### 7. Bridge — Мост

**Тип:** структурный паттерн проектирования.

**Определение:**  
Разделяет абстракцию и её реализацию, позволяя изменять их независимо друг от друга.

**Ключевая мысль:**  
Абстракция и реализация развиваются отдельно.

**Пример:**  
`RemoteControl` работает отдельно от `Device`, поэтому один пульт можно использовать с разными устройствами.

---

### 8. Composite — Компоновщик

**Тип:** структурный паттерн проектирования.

**Определение:**  
Позволяет объединять объекты в древовидные структуры и работать с отдельными объектами и их группами одинаковым образом.

**Ключевая мысль:**  
Один объект и группа объектов имеют общий интерфейс.

**Пример:**  
В файловой системе `File` и `Directory` реализуют общий интерфейс `FileSystemItem`.

---

### 9. Decorator — Декоратор

**Тип:** структурный паттерн проектирования.

**Определение:**  
Позволяет динамически добавлять объекту новое поведение, не изменяя его исходный класс.

**Ключевая мысль:**  
Добавляем поведение через обёртку.

**Пример:**  
В Java `InputStream` можно оборачивать в `BufferedInputStream`, добавляя буферизацию.

---

### 10. Facade — Фасад

**Тип:** структурный паттерн проектирования.

**Определение:**  
Предоставляет простой интерфейс для работы со сложной подсистемой, скрывая её внутреннюю сложность.

**Ключевая мысль:**  
Сложную систему прячем за простым интерфейсом.

**Пример:**  
`OrderFacade.placeOrder()` внутри вызывает проверку товара, оплату, создание доставки и отправку уведомления.

---

### 11. Flyweight — Приспособленец

**Тип:** структурный паттерн проектирования.

**Определение:**  
Позволяет уменьшить потребление памяти за счёт совместного использования общих частей состояния между большим количеством объектов.

**Ключевая мысль:**  
Общие данные хранятся один раз и переиспользуются.

**Пример:**  
Текстовый редактор может использовать один объект шрифта для множества символов вместо создания отдельного объекта шрифта для каждого символа.

---

### 12. Proxy — Заместитель

**Тип:** структурный паттерн проектирования.

**Определение:**  
Предоставляет объект-заместитель, который контролирует доступ к настоящему объекту и при необходимости добавляет дополнительную логику до или после вызова.

**Ключевая мысль:**  
Работаем с настоящим объектом через посредника.

**Пример:**  
В Spring `@Transactional` работает через прокси: прокси открывает транзакцию, вызывает настоящий метод, а затем выполняет `commit` или `rollback`.

---

# Поведенческие паттерны

### 13. Strategy — Стратегия

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Определяет семейство алгоритмов и выносит их в отдельные классы, которые можно взаимозаменять без изменения основного кода.

**Ключевая мысль:**  
Меняем алгоритм, не переписывая основной код.

**Пример:**  
Разные способы оплаты реализованы как отдельные классы: `CardPayment`, `SbpPayment`, `PayPalPayment`. Приложение может менять их без изменения основной логики.

---

### 14. Observer — Наблюдатель

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Определяет отношение один ко многим: при изменении внутреннего состояния издатель оповещает подписчиков, а подписчики в свою очередь сами решают, как на это реагировать.

**Ключевая мысль:**  
Издатель уведомляет подписчиков об изменениях.

**Пример:**  
Есть издатель новостей и несколько подписчиков. Когда появляется новая новость, издатель оповещает всех подписчиков, а каждый подписчик сам решает, что делать с уведомлением.

---

### 15. Command — Команда

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Превращает запрос или действие в отдельный объект, благодаря чему его можно хранить, передавать, откладывать, отменять или выполнять позже.

**Ключевая мысль:**  
Действие превращается в объект.

**Пример:**  
В текстовом редакторе действия `Copy`, `Paste`, `Undo` представлены отдельными объектами-командами.

---

### 16. State — Состояние

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Позволяет объекту изменять своё поведение в зависимости от его внутреннего состояния, вынося поведение разных состояний в отдельные классы.

**Ключевая мысль:**  
Меняется состояние — меняется поведение объекта.

**Пример:**  
Заказ может находиться в состояниях `New`, `Paid`, `Shipped`, `Cancelled`, и в каждом состоянии вести себя по-разному.

---

### 17. Template Method — Шаблонный метод

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Определяет общий алгоритм выполнения операции в базовом классе, оставляя отдельные шаги для реализации или переопределения в подклассах.

**Ключевая мысль:**  
Общий алгоритм один, отдельные шаги могут отличаться.

**Пример:**  
При приготовлении напитка общий алгоритм: вскипятить воду → заварить → налить. Для кофе и чая отличается способ заваривания.

---

### 18. Chain of Responsibility — Цепочка обязанностей

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Передаёт запрос последовательно по цепочке обработчиков, пока один из них не обработает запрос или цепочка не закончится.

**Ключевая мысль:**  
Запрос проходит через цепочку обработчиков.

**Пример:**  
HTTP-запрос проходит через цепочку фильтров Spring Security, каждый из которых выполняет свою проверку.

---

### 19. Mediator — Посредник

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Уменьшает связанность между объектами, заставляя их взаимодействовать через отдельный объект-посредник.

**Ключевая мысль:**  
Объекты общаются не напрямую, а через посредника.

**Пример:**  
В чат-системе пользователи отправляют сообщения через `ChatMediator`, а не обращаются напрямую друг к другу.

---

### 20. Memento — Снимок

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Позволяет сохранять состояние объекта и восстанавливать его позже, не нарушая его инкапсуляцию.

**Ключевая мысль:**  
Сохраняем состояние и можем вернуться к нему.

**Пример:**  
`Undo` в текстовом редакторе восстанавливает предыдущее состояние документа.

---

### 21. Iterator — Итератор

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Предоставляет способ последовательно перебирать элементы коллекции, не раскрывая её внутреннее устройство.

**Ключевая мысль:**  
Перебираем коллекцию через единый интерфейс.

**Пример:**
```java
Iterator<String> iterator = list.iterator();

while (iterator.hasNext()) {
    System.out.println(iterator.next());
}
```

---

### 22. Visitor — Посетитель

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Позволяет добавлять новые операции над объектами, не изменяя классы этих объектов.

**Ключевая мысль:**  
Добавляем новые операции без изменения существующих классов.

**Пример:**  
Для файловой системы можно создать `SizeVisitor`, который считает размер файлов, и `PrintVisitor`, который выводит их имена.

---

### 23. Interpreter — Интерпретатор

**Тип:** поведенческий паттерн проектирования.

**Определение:**  
Определяет грамматику некоторого языка и предоставляет механизм интерпретации выражений этого языка.

**Ключевая мысль:**  
Разбираем выражение по заданным правилам и выполняем его.

**Пример:**  
Простой калькулятор разбирает выражение `2 + 3 * 4` и вычисляет результат.
